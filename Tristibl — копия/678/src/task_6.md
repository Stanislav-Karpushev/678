# Тестовый сценарий: Путь абитуриента в «Школу 21» (end-to-end)

## 1. Общие сведения

| Параметр | Значение |
|----------|----------|
| **Название** | Сквозная проверка поступления на основное обучение через 21-school.ru |
| **Вид проверки** | End-to-end (сквозной пользовательский путь) |
| **Задача** | Убедиться, что абитуриент способен пройти все отборочные этапы и получить приглашение на обучение |
| **Основание** | Страница https://21-school.ru/admission и блок FAQ на ней |

---

## 2. Действующие лица

| Участник | Описание |
|----------|----------|
| **Абитуриент** | Пользователь, подающий заявку на основное обучение (с 18 лет, без верхней границы; в «бассейн» можно с 17 лет при письменном согласии родителей) |
| **Платформа «Школа 21»** | Сайт 21-school.ru, личный кабинет, среда вступительной игры и «бассейна» |
| **Кампус** | Офлайн-площадка, где проходит отборочный интенсив |

---

## 3. Исходные условия

1. Абитуриенту исполнилось 18 лет (для основного обучения); для участия в «бассейне» допускается возраст 17 лет при письменном согласии родителей.
2. Есть действующий email, ранее не использованный для регистрации в «Школе 21» (регистрация с почты возможна один раз).
3. Есть устройство с браузером и стабильный интернет.
4. Абитуриент готов выделить 14 дней на очный «бассейн» с нагрузкой до 10 часов в день.

---

## 4. Входные данные

| Параметр | Пример |
|----------|--------|
| Возраст | 18+ (основное обучение); 17 с согласием родителей (для «бассейна») |
| Email | valid.user@example.com (ранее не использованный) |
| Кампус | Выбирается из списка на странице поступления |
| Программа | Выбирается из списка (можно поменять после «бассейна») |
| Документы | Файлы поддерживаемого формата (загружаются на 3-м этапе, затем распечатываются и подписываются вручную) |

---

## 5. Основной путь (Happy Path)

| Шаг | Действие абитуриента | Ожидаемый результат |
|-----|----------------------|---------------------|
| **1** | Открывает https://21-school.ru/admission | Страница загружается, видны этапы поступления и кнопка подачи заявки |
| **2** | Выбирает кампус и программу, создаёт личный кабинет | Кабинет создан, открыт доступ к вступительной игре и к записи на «бассейн» после игры |
| **3** | Проходит **1-й этап — вступительная игра (~60 мин)** | Игра запускается, абитуриент решает задачи в роли разработчика, набирает нужное число XP и получает приглашение дальше |
| **4** | Проходит **2-й этап — просмотр видео о школе (~15 мин)** | В кабинете открывается видео; после просмотра этап отмечается пройденным |
| **5** | Проходит **3-й этап — загрузка документов (~10 мин)** | Абитуриент заполняет форму, загружает документы (их нужно распечатать и подписать); система подтверждает загрузку |
| **6** | Получает приглашение и проходит **4-й этап — отборочный «бассейн» (14 дней, очно)** | Работа с Python и ИИ-инструментами, Git/GitLab, знакомство с 7 цифровыми профессиями, индивидуальные и групповые проекты, экзамены |
| **7** | Ожидает результатов «бассейна» | Система/кампус сообщает результат: при успехе — приглашение на основное обучение |

**Постусловие:** при успешном прохождении «бассейна» абитуриент получает приглашение на основное обучение и может быть зачислен.

---

## 6. Альтернативные ветки и исключения

| ID | Ситуация | Ожидаемое поведение |
|----|----------|---------------------|
| **A1** | Не набрано нужное число XP на 1-м этапе | Доступ к следующему этапу не открывается; попытку можно повторить. После прохождения отборочных игр число попыток на «бассейн» не ограничено |
| **A2** | Документы загружены в неподдерживаемом формате | Система показывает ошибку и просит загрузить файл в допустимом формате |
| **A3** | «Бассейн» не пройден | Приглашение на основное обучение не выдаётся. Повторная регистрация с той же почты невозможна, но в существующем кабинете после игр можно записываться на «бассейн» неограниченно |
| **A4** | Абитуриент младше 18 лет | К основному обучению не допускается; в «бассейн» можно с 17 лет при письменном согласии родителей |
| **A5** | Повторная регистрация с той же почты | Новый кабинет не создаётся; регистрация с почты возможна только один раз |

---

## 7. Состояния после выполнения

**При успехе:**
- Абитуриент получает приглашение на основное обучение.
- Может выбрать направление и начать учёбу.

**При неуспехе (альтернативные ветки):**
- Остаётся на текущем этапе или получает отказ.
- Может повторить попытку по правилам: повторная регистрация с той же почты невозможна, но в существующем кабинете после игр можно записываться на «бассейн» неограниченно.

## 8. Пояснение: чем тестовый сценарий отличается от use case

Этот документ — **тестовый сценарий** (test scenario), а не сценарий использования (use case). Разница:

| Критерий | Тестовый сценарий (этот документ) | Use case |
|----------|-----------------------------------|----------|
| **Назначение** | Проверка работоспособности системы через сквозной поток | Описание требований к взаимодействию пользователя с системой |
| **Кто использует** | QA-инженер | Аналитик / проектировщик |
| **Детализация** | Верхнеуровневая, с проверочными точками и ожидаемыми результатами | Описание цели пользователя и шагов к ней |
| **Пример** | «Проверить, что абитуриент проходит от игры до приглашения на обучение» | «Абитуриент хочет поступить, для этого выполняет этапы…» |

Тестовый сценарий проверяет **как система работает**, use case описывает **что система должна делать для пользователя**.

### Пример use case (для сравнения)

- **Кто:** абитуриент, желающий поступить в «Школу 21».
- **Что хочет:** пройти отбор и попасть на основное обучение.
- **Цель:** получить приглашение на обучение.
- **Шаги:** подать заявку → игра → видео → документы → «бассейн» → результат.
- **Реакция системы:** открывает следующий этап после успешного прохождения предыдущего, сообщает результат «бассейна».
